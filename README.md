# 门店日报

门店日报系统：当天填数、本月自动累计、复制进微信群。同时管触客、垫资、通报表和月度考核。

个人微信没有官方机器人，所以现在是 **保存 → 复制 → 贴群**。数据按多店、多角色建好，加店换人不用推倒。

## 谁用

| 角色 | 典型人 | 能做什么 |
|---|---|---|
| 管理员 | 运营 | 全店、看板、考核、兑付、账户、备份 |
| 填报员 | 店员 | 本店日报 / 触客 / 垫资 |
| 只读 · 店长 | 店长 | 看本店报表、通报、垫资，不能改数 |
| 只读 · 区域经理 | 区域经理 | 看辖区上述内容，不能改数 |
| 地市负责人 | 地市经理 | 看本市范围；本市日报可改（本月过去日）；垫资 / 触客只读；次月 1–5 日给顾问打「地市分」 |

店长靠账户绑店；区域经理的范围是门店档案里的「区域经理」姓名；地市负责人按门店档案的「地市」圈范围（建号 / 改范围都在设置页，选有效地市）。

默认口令登录后必须先改密，不能改回 `123456`。

## 页面

- **今日填报**：只改「日」，累计自动算；可复制群播报
- **触客播报 / 记录**：一单一单记开口；「成交」只是结果。成功率 = 已成交 ÷ 全部触客
- **垫资**：本月流水。门店记账必须带号码；已兑付锁定，管理员可取消兑付后再改
- **报表**：单店日报 / 周报 / 月报，可导出 Excel
- **通报表**：有移动编码的店一行一张；复盘文案可换模板（标准/检查/表彰/精简等），平台名/公司名可在设置里改
- **销量对比**：单日全店一张表，两层表头——「当日」4 列（触客条数 / 手机销量 / 差 / 业辅查询登记）+「本月累计」4 列（同样四个数，本月 1 日到所选日）；差写成「少报 +4 / 多报 −3 / 一致 / 未交日报」，差率跟在差格后面小字；表本身用通报表同款网格（1px 细线、表头浅灰加粗、门店列左对齐）；筛选也照通报表——日期 + 地市 + 区域经理（地市默认「全部」，判不着的人不显示这一栏），筛选同时管表、通报文案、通报图片和 Excel；可切单店按月逐日，可导出 Excel（单日 16 列，带提交人 / 时间）；页面带可复制的通报文案和「复制图片 / 下载图片」（图就是这张表，抬头带日期和筛选范围）。管理员 / 地市负责人能就地改手机销量和业辅查询登记（地市只能改本市），未交日报的店不给改
- **政策说明**：开关打开后须先点「已阅读」，未确认不能进其他页（填报员、店长、区域经理都一样）
- **洞察**：本月进度对时间、本周 vs 上周合计与分店明细；可按地市、区域经理筛
- **开票申请**：按税务样表导出酬金 / 租赁申请三张表；开票回填结算
- **多店看板 / 月度考核 / 修改审计 / 登录日志**：仅管理员。日报、触客、垫资、开票、移动校准的改动和登录/退出都留痕，记真实来源 IP
- **企业微信播报**：保存日报 / 触客后自动发群（全局 + 按地市覆盖），失败不挡填报
- **设置**：管理员管账户、门店、目标、规则、政策、开票主体、备份；其他人只能改自己口令。门店档案可停用 / 删除（有填报的只能停用）

管理员看成交记录默认今天全店，看垫资默认本月全店，可按地市、区域经理再筛。

## 口径（别改错）

- 只存「日」。累 = 本月 1 号到所选日期合计，月初自动清零
- 考核奖罚按系统规则；实际酬金 = 开票 + 房补 − 垫资
- 未交日报不考核（标「本月未交」，净额 0）
- 通报：没有 `mobile_code` 的店不进表
- 触客：同店 + 当日 + 同号码覆盖；当天可改可删，往日只读
- 号码页面默认打码
- 登录日志：局域网记内网地址；走 Cloudflare 记公网地址
- 新口令至少 8 位，不能用默认值、重复数字或连续数字；默认口令登录后必须先改
- 销量对比：触客条数 = 当天全部触客记录条数（不分成交），只认当天；触客没有补交一说，隔天补记的算补记那天，不回填前一天
- 销量对比：差 = 触客条数 − 手机销量（正 = 少报、负 = 多报）；差 0 也列；未交日报的店留行但差不计算；触客 0 条不算差率（分母 0）
- 销量对比：合计只算已交日报的店 / 天，未交的单独点名；改手机销量沿用现有权限（管理员 / 地市负责人），留修改审计痕迹，改完不重发群播报
- 销量对比：通报文案与通报图片都跟页面用同一份数，行序固定按 |差| 降序（跟页面排序开关无关，同一份数据不该复制出两种顺序）；图片走 html2canvas 截图，微信 / 手机里只出预览让长按保存

- 销量对比：表里「本月累计」4 列 = 当月 1 日 → 所选日，按当前筛选（地市 / 区域经理）算，每个店一行；触客含未交日报那几天（触客本来就照记），本月手机销量 / 差只算这月交过日报的店（一天都没交就差写「—」），业辅只可能出自已交日报——是「这段时间干出来多少」，不是表里那个「已交日报的合计」；合计行就是表里看得见那几行的加总
- 销量对比：业辅查询登记每店每天一个整数，跟手机销量一样就地填、就地改（管理员 / 地市负责人，地市限本市、本月），只给已交日报的店填；只留「谁、什么时候」在格子上（悬停看），不进「修改审计」页——那页按指标字典渲染，混进来会把一件登记当成日报指标

## 本地开发

```bash
cd /path/to/store-daily
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export STORE_DAILY_SECRET='换成一段随机字符串'
.venv/bin/python wsgi.py
```

浏览器打开 http://127.0.0.1:5055。没设随机 `STORE_DAILY_SECRET` 或仍是示例值，生产模式会拒绝启动。

```bash
.venv/bin/pip install pytest
.venv/bin/pytest -q
```

`tests/conftest.py` 提供现成夹具，新用例不用手写登录：`tmp_db`（全新库）、`client` / `admin_client` / `filler_client` / `city_client`（对应角色已登录）、`store_id()` 按门店 code 查 id。回归测试写进对应功能文件，不再建 `*_regression` 堆积文件。

门店目录：公开仓库只有示例店 `app/stores_seed.py`。真实店名、人员放 `app/stores_seed_local.py`（不进 git）。生产机有这份文件就会用真实目录；测试设 `STORE_DAILY_SAMPLE_SEED=1` 强制示例店。

## 生产

店员入口走 **Cloudflare 域名**（Tunnel）。只在一处写库。

复制 `.env.example` 为 `.env`，填入主机和密钥后再同步：

```bash
# 同步代码到生产机（默认不覆盖库）
./scripts/sync_to_vps.sh
```

本机 `data/store_daily.db` 是开发/测试库，**不是生产库**。日常部署只推代码。只有本机库确认是最新生产快照时，才用 `./scripts/sync_to_vps.sh --with-db`。

机外备份读 `scripts/backup.env`（不进 git）。拷库必须用 SQLite backup API，禁止直接 `cp *.db`。代码 bundle 每次部署推一份到两台灾备机，自动只留最新 10 份（`CODE_BUNDLE_KEEP` 可改）；备份机是手机时脚本会先清本机 ARP，避免其「隐私 MAC」重连换地址后长时间连不上。

## 数据

默认库 `data/store_daily.db`，`.env` 不进 git。换路径：

```bash
export STORE_DAILY_DB=/path/to/store_daily.db
export STORE_DAILY_DATA=/path/to/data
export STORE_DAILY_SECRET='随机长串'
```
